## Completion rule

The repository's roadmap is represented by the M0–M11 milestone history in `TESTING.md`, `artifacts/milestone-status.md`, the source tree, and the current issue/PR backlog. A milestone is only treated as complete when its stated implementation, automated checks, and required manual gates have current evidence. Historical claims are retained as context, not as fresh validation.

## Evidence legend

- **Implemented:** Source and documentation are present; runtime evidence may still be pending.
- **Verified:** Current validation in this working copy or a reproducible local environment supports the claim.
- **Missing:** Required capability is absent from the source or acceptance path.
- **In progress:** Work is actively being implemented or validated.
- **Blocked:** Cannot be validated or completed without a missing environment, owner decision, external service, or other prerequisite.
- **Assumption:** A design choice made because the roadmap does not specify a more precise behavior.

## Architecture and end-state comparison

The implemented system is a multi-application TypeScript monorepo: candidate web app, employer portal, admin portal, Fastify API, PostgreSQL/Drizzle persistence, shared contracts/domain packages, filesystem object storage, and MEH offline/connected modes. This is materially broader than a single candidate CRUD demo and covers the documented M0–M11 feature surface.

The remaining end-state gaps are primarily evidence and operational maturity rather than an absent M12 feature list: committed automated tests, fail-closed production configuration, deployment/rollback/backup/observability documentation, and completion of the M11 visible browser journey. Payment, live opportunity feeds, employer integrations beyond the implemented invitation/projection workflow, and external AI provider operation remain configuration- or product-dependent rather than safe defaults.

## Assumptions

- “Roadmap-complete” means complete against the repository’s documented M0–M11 roadmap, not an unbounded future product vision that is not present in this repository.
- Local validation uses synthetic accounts and local-only service endpoints.
- No external payment, email, AI provider, production database, or deployment target will be contacted.
- Dependency upgrades are not automatically accepted solely because Dependabot proposed them; each must pass compatibility review.

## Blockers

- Production deployment, PR merge, and publication beyond draft PR #3 are intentionally not authorized.
- The visible M11 walkthrough is blocked by unavailable Docker/PostgreSQL/local services in this environment; automated CI browser evidence is separate.
- A production secrets store, host, rollback target, monitoring destination, and owner security sign-off are not supplied.
